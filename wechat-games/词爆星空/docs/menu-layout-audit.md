# MenuScene 布局审查报告

**审查日期**: 2026-04-29  
**审查文件**: `src/js/scenes/MenuScene.js`  
**基准参数**: `BASE_WIDTH = 390`, `BASE_HEIGHT = 844`  
**缩放公式**: `dw(val) = val × (screenWidth / 390)`, `dh(val) = val × (screenHeight / 844)`  
**分析画布**: 390 × 844 (iPhone 12/13 Pro 逻辑分辨率，与设计稿基准一致)

---

## 一、核心问题诊断

### 根本原因

代码中使用的是 **750 设计稿坐标**（注释 `// 居中：375是设计稿中心` 表明作者将 750 作为设计稿宽），但 `dw()/dh()` 函数是基于 `BASE_WIDTH=390` 缩放的。这导致所有 >390 的 x 坐标全部溢出屏幕右边界。

**证据链**：
- 注释写 `dw(375 - 200) // 居中：375是设计稿中心` → 设计稿宽为 750
- 实际 `dw(375)` = `375 × (390/390)` = **375px**，而不是设计稿中心 195px
- 排行榜按钮 `x=dw(410)` = **410px**，在 390 宽屏幕上从 410~670 完全不可见

## 四、修正建议 (基于 390 基准)

### 设计原则
- 屏幕有效布局宽度 = 390，内容宽度 = 390 - 左右边距
- 按钮和资源栏应完全在 390×844 内
- 底部元素需考虑安全区（建议底部留白 ≥ 20px）

### 4.1 按钮布局修正

```
// 开始游戏按钮 — 居中，宽度不超过屏幕 85%
x: dw(35),          // (390 - 320) / 2 ≈ 35, 左右各留 35px
y: dh(580),
w: dw(320),         // 降为 320 (原 400)
h: dh(88),

// 商店按钮 — 左下
x: dw(30),
y: dh(740),
w: dw(160),         // 降为 160 (原 260)
h: dh(72),

// 排行榜按钮 — 右下
x: dw(200),         // (30 + 160 + 间隙) → 390 - 30 - 160 = 200
y: dh(740),
w: dw(160),         // 降为 160 (原 260)
h: dh(72),
```

**按钮总宽度**: 30 + 160 + 10(gap) + 160 + 30 = 390 ✅ 恰好填满

### 4.2 资源栏修正

```
// 三等分布局 (总可用宽度 390 - 30*2边距 = 330，每项 110)
资源项1: x = dw(30 + 110/2) = dw(85)
资源项2: x = dw(30 + 110 + 110/2) = dw(195)  // 屏幕中央
资源项3: x = dw(30 + 110*2 + 110/2) = dw(305)

// 卡片尺寸
卡片半宽: dw(50),  // 原 70，缩小以适应三等分
y: dh(420)
```

### 4.3 装饰星星修正

```js
const stars = [
  [40, 100], [350, 80], [80, 300], [310, 250],
  [50, 500], [340, 450], [180, 150], [200, 380]

// 所有 x 坐标 < 390
```

### 4.4 底部文字修正

```
y: dh(820)  // 原 880 → 820, 距底部 24px (844-820=24)
```

## 五、根因与预防建议

1. **设计稿统一**: 确保所有开发者使用同一个设计稿基准（建议 390×844 与代码 `BASE_WIDTH`/`BASE_HEIGHT` 一致），或在使用 2x 设计稿（750）时将 `BASE_WIDTH` 也改为 750。
2. **代码审查检查点**: 任何 `dw(x)` / `dh(y)` 调用应确保 `x ∈ [0, 390]` 且 `y ∈ [0, 844]`。
3. **自动化检测**: 建议在 `dw()` / `dh()` 中加入开发环境断言，当参数超出设计稿范围时打印警告。
4. **同屏设备测试**: 在 375×667 (iPhone 8)、390×844 (iPhone 13)、414×896 (iPhone 11) 三种分辨率下验证布局。
